Internal Developer Platform

Kubernetes as the API.
Git as the source of truth.

A self-service developer platform designed to remove infrastructure complexity from everyday development. Developers onboard services, provision databases and manage deployments through standardized workflows, while Kubernetes operators and GitOps handle the automation.

  • Developer self-service. Services, databases and deployments start from a form, not from infrastructure tooling.
  • Reduced cognitive load. Complex infrastructure workflows sit behind a few simple, standard interfaces.
  • Consistent delivery. Every change is a reviewed, auditable commit, applied the same way in every environment.

Onboard a Service · 97 seconds

Goal
A new service, running in dev.
In Backstage
Name, owner and template. Review and merge the pull request it opens.
Automated
The repository is created and scaffolded with CI; the first build deploys to dev through GitOps.
Outcome
A healthy service on a public HTTPS URL, with its rollout and metrics in the portal.

Onboard a Database · 3 minutes

Goal
A Postgres database for an existing service.
In Backstage
Three short forms: request it, apply its schema, bind it. Each opens a pull request.
Automated
The database is provisioned on AWS, its credentials stored, its migrations applied forward-only.
Outcome
The service's pods start with the credentials mounted. No secret ever passes through Git.

Code

Built end-to-end

Designed and implemented by one engineer, from the AWS infrastructure to the developer portal. Each repository owns one part of the platform and documents it in its README.

  • 4 Go operators built with Kubebuilder, each owning one platform resource.
  • A platform API of four resources: Component, Release, Database and DatabaseSchema.
  • Backstage golden paths that end in pull requests, and portal views of rollouts, metrics and schemas.
  • Three EKS clusters on AWS, all delivered from one management cluster.

Platform control plane start here

component-operator

Reconciles Component into its GitHub repository and scaffold request.

release-operator

Turns Release intent into GitOps deployment commits, including auto-deploy.

schema-operator

Releases a service's database schema on its own, as a versioned migration package.

scaffold-operator

One-time, versioned repository scaffolding from golden-path templates.
