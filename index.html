Architecture

The platform at a glance

A developer only ever talks to Backstage. Everything after that is Git, and the automation that reconciles it.

  1. Git is the system of record. Golden paths open pull requests; a person merges them. Platform intent (Component, Release, Database) and deployment state live in one GitOps repository.
  2. The management cluster runs only the platform. Argo CD applies Git to it and reaches out to the workload clusters, which run only services. Nothing in a workload cluster can change the platform.
  3. Runtime state flows back. Rollout status, health and metrics from every environment end up in the same portal the request started from.

Developer experience

Backstage templates are the golden paths: a few questions, then a pull request opened as the platform's own GitHub App. The same portal shows each service's versions, rollouts, metrics, logs and dependencies.

Platform APIs & operators

Component is an identity; Release and Database point back to it. Three Go operators reconcile them: one creates the repository, one scaffolds it from a versioned template, one turns releases into deployment commits.

GitOps delivery

One Argo CD on the management cluster reads one GitOps repository through four ApplicationSets and deploys to every cluster, matched by an environment label. Webhooks make a merge show up in seconds.

Infrastructure provisioning

Crossplane exposes infrastructure as Kubernetes APIs, shipped as versioned packages: GitHub repositories for every component, and RDS databases whose credentials reach services through Secrets Manager.

Observability

Every scaffolded service exposes metrics with the same identity labels. Each cluster's Prometheus remote-writes to a central Mimir, which Grafana and the portal read, so every service is observable from day one.

Design decisions

The choices behind it

The full reasoning lives in the architecture docs.

A small API, not a mega-CRD

Component is just an identity record. Databases, releases and queues are independent resources that point back to it, so each can evolve on its own instead of turning one CRD into an orchestration engine.

Git is the record of what runs where

Onboarding, deploys and auto-deploys all end as commits in one GitOps repo. Every change is reviewable and revertable, and the cluster can be rebuilt from Git.

Bots, not personal tokens

The portal, the scaffolder and the release automation each commit as their own GitHub App with short-lived, narrowly scoped tokens; CI reaches AWS through OIDC with no stored secrets.

Disposable clusters, durable state

The EKS clusters are created and destroyed daily to keep cost down. DNS, certificates, secrets and Terraform state live outside them, so a fresh cluster converges from Git in minutes.

Safe to show the public

Guests browse the live portal read-only. Metrics come from fixed server-side queries, so a visitor can't send PromQL; logs and templates are owner-only.

Observability by default

Every scaffolded service exposes the same metrics and identity labels, so one dashboard and one portal tab cover every service and environment with no per-service setup.
