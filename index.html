Golden paths

See the platform in action

Two golden paths, each a real run edited for length. The developer only fills in forms; everything after them is the platform.

Onboard a Service · 97 seconds

  1. 1

    Define the service

    Name, owner, scaffold template and version, auto-deploy to dev. That's the whole developer input.

  2. 2

    The platform takes over

    Backstage opens a pull request with a Component and its first Release. A human reviews and merges it, like any change.

  3. 3

    GitOps deploys it

    Argo CD syncs the merge; Crossplane creates the GitHub repo and its webhook; an operator commits the scaffold; CI builds the image.

  4. 4

    Healthy and observable

    The first green build rolls out to dev on its own. Rollout state, metrics and a public HTTPS endpoint appear in the portal.

Onboard a Database · 3 minutes

  1. 1

    Request a database

    Pick the service, the environment and a size. Backstage opens a pull request with one Database.

  2. 2

    Crossplane provisions it

    Argo CD syncs the merge; Crossplane creates a real RDS Postgres with its network and password, and publishes the connection details to Secrets Manager.

  3. 3

    Apply the schema

    A second pull request adds a DatabaseSchema pointing at a published version. Atlas applies its migrations, forward-only.

  4. 4

    Bind it to the service

    A third pull request names the database on the service's Release. The new pods start with its credentials mounted as files.

Architecture

The platform at a glance

A developer only ever talks to Backstage. Everything after that is Git, and the automation that reconciles it.

  1. Git is the system of record. Golden paths open pull requests; a person merges them. Platform intent (Component, Release, Database, DatabaseSchema) and deployment state live in one GitOps repository.
  2. The management cluster runs only the platform. Argo CD applies Git to it and reaches out to the workload clusters, which run only services. Nothing in a workload cluster can change the platform.
  3. Runtime state flows back. Rollout status, health and metrics from every environment end up in the same portal the request started from.

Developer experience

Backstage is the only interface a developer needs. Every golden path ends in a pull request, and every result, from rollouts to metrics, is read back into one page per service.

Golden-path scaffolding

Every new service starts from a versioned template that already builds, ships, runs safely and shows up in monitoring and the portal, rendered once as a single commit.

Platform API & operators

Component is just an identity. Releases, databases and their schemas are independent resources that point back to it through componentRef, each reconciled by its own controller.

Read more →

Service bindings

A service asks for a database by name. Crossplane provisions it, Secrets Manager holds its credentials, and the pod reads them as files. No credential ever passes through Git.

Read more →

Database schemas

Code can be rolled back; data can't. A service's schema is released on its own, through its own pull request, and only moves forward, so a code rollback never touches the database.

Read more →

GitOps delivery

One repository records what runs where. Each kind of file in it is read by its own Argo CD ApplicationSet, and every change, by a person or a bot, is a commit.

Read more →

Hub and spoke

One management cluster runs the whole platform: Argo CD, Backstage, Mimir and the operators. Dev and prod only run services, so every environment is deployed and observed from one place.

Read more →

Observability

Every service is observable from its first deploy. Two labels decide which metrics leave each cluster, and one store serves Grafana and the portal for every environment.

Code

Every part is public

Each repository's README explains its part; the architecture pages show how they fit together.

backstage

The developer portal: golden-path templates, deployments, metrics, guest access.

component-operator

Reconciles Component into its GitHub repository and scaffold request.

scaffold-operator

One-time, versioned repository scaffolding from golden-path templates.

release-operator

Turns Release intent into GitOps deployment commits, including auto-deploy.

schema-operator

Releases a service's database schema on its own, as a pointer to a versioned migration package.

platform-scaffolds

The versioned service templates every new repository starts from.

crossplane-compositions

Infrastructure APIs (GitHub repositories, Postgres) released as OCI packages.

application-repositories

The GitOps source of truth: what deploys where.

argocd

Bootstraps the Argo CD ApplicationSets on the management cluster.

helm-charts

Charts for cluster-wide platform resources, supporting infrastructure and the database schema package.
